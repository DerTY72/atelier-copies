# Atelier Copies

Интернет-магазин копий картин. В проекте есть витрина, личный кабинет,
заказы, отзывы с модерацией и админка. Серверная версия работает на Next.js и
PostgreSQL через Prisma.

## Публичная витрина

[atelier-copies на GitHub Pages](https://derty72.github.io/atelier-copies/)

Статическая версия использует ту же витрину: каталог с фильтрами, карточки работ,
корзину с проверкой суммы и сохранением в браузере, а также помощник с FAQ. Для регистрации, заказов,
загрузки отзывов и отправки писем требуется серверная версия.

Запуск статической витрины на Windows:

```powershell
npm.cmd ci
npm.cmd run dev:portfolio
```

Публикация через GitHub Pages: в настройках репозитория откройте **Settings → Pages**,
выберите **GitHub Actions** в поле **Source** и запустите workflow **Publish portfolio**.
При следующих обновлениях ветки `main` витрина пересобирается автоматически.
Сборка выводится в `portfolio/out` командой `npm run build:portfolio`.

## Запуск полной версии

Установите зависимости из корня проекта:

```powershell
npm.cmd ci
npm.cmd run db:generate
```

Подготовьте базу по инструкции [Локальная настройка PostgreSQL](#локальная-настройка-postgresql)
и запустите сайт:

```powershell
npm.cmd run dev
```

После запуска сайт будет доступен на `http://localhost:3000`.

## Старый прототип

Файлы `index.html`, `styles.css` и `script.js` оставлены как первая статическая
версия. Основная разработка теперь идет в папке `app`.

## Ближайшие этапы

1. Настроить `.env` по примеру `.env.example`.
2. Создать базу `atelier_copies` в PostgreSQL.
3. Запустить `npm.cmd run db:push` и `npm.cmd run db:seed`.
4. Добавить смену email с повторным подтверждением.
5. Подключить отправку реальных писем через SMTP или почтовый сервис.
6. Подключить реального платежного провайдера к уже подготовленной платежной модели.
7. При желании подключить языковую модель к уже готовому гибридному чат-помощнику.

## База данных

Схема Prisma находится в `prisma/schema.prisma`. Пока `DATABASE_URL` не задан,
сайт использует fallback-товары из `app/products.ts`. После настройки PostgreSQL
товары будут читаться из базы.

## Заказы

Клиентская корзина отправляет имя, email, телефон, способ доставки, адрес,
комментарий и позиции заказа в `POST /api/orders`. Сервер заново получает товары
из базы, пересчитывает сумму и сохраняет заказ в таблицы `Order` и `OrderItem`.
Статус нового заказа: `PENDING_PAYMENT`.

После создания заказа покупатель попадает на `/orders/[id]`. Последние заказы
можно посмотреть на `/admin/orders`; там администратор видит контакт покупателя,
доставку, адрес и комментарий.
Администратор может менять статус заказа через `PATCH /api/admin/orders/[id]`.

## Товары

Администратор управляет каталогом на `/admin/products`: может добавить товар,
изменить название, автора, стиль, размер, цену, описание, изображение и видимость
в каталоге. Создание идет через `POST /api/admin/products`, обновление через
`PATCH /api/admin/products/[id]`.

Изображение можно указать ссылкой или загрузить файлом. В учебной локальной версии
загруженные файлы сохраняются в `public/uploads/products` и игнорируются Git.

## Отзывы

Авторизованный пользователь может оставить один отзыв в модальном окне товара:
текст обязателен, а фото или видео можно прикрепить как вложение. Новый отзыв
получает статус `PENDING` и не показывается в каталоге до модерации.

Администратор видит последние отзывы на `/admin/reviews` и может менять статус
через `PATCH /api/admin/reviews/[id]`. В карточках товаров показываются только
одобренные отзывы.

Отзывы отправляются в `POST /api/reviews`. В учебной локальной версии вложения
сохраняются в `public/uploads/reviews`; сами загруженные файлы игнорируются Git,
а папка остается в проекте через `.gitkeep`.

## Поддержка

Форма поддержки на главной странице отправляет обращение в `POST /api/support`.
Сообщение сохраняется в таблицу `SupportMessage` со статусом `OPEN`.

Администратор видит последние обращения на `/admin/support` и может менять статус
через `PATCH /api/admin/support/[id]`. Ответ на email клиента пока остается
ручным действием администратора.

## Чат-помощник

На главной странице есть плавающий чат, который отправляет вопросы в `POST /api/chat`.
Сейчас он работает без Ollama и внешних API: сначала ищет подходящий FAQ-сценарий, а для запросов вроде
`покажи картины до 90000`, `подобрать модерн` или `есть импрессионизм` читает актуальные товары через
`getCatalogProducts()`. Поэтому после изменения каталога в админке бот сразу использует новые названия,
цены, стили и изображения.

Базовые сценарии покупателя: доставка, оплата, сроки изготовления, размеры и рамы, подбор по бюджету,
статус заказа, возврат, отзывы, поддержка, регистрация и восстановление пароля. Нестандартные вопросы
бот направляет в форму поддержки.

## Email-уведомления

После создания заказа сайт готовит два письма: администратору и покупателю. После
обращения в поддержку сайт готовит письмо администратору. При регистрации сайт
отправляет письмо со ссылкой подтверждения email. Если SMTP не настроен, письма
сохраняются в `storage/email-dev.log`.

Для реальной отправки заполните в `.env` значения `MAIL_MODE=smtp`, `MAIL_FROM`,
`MAIL_ADMIN_TO`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER` и `SMTP_PASSWORD`. Для SMTP
на 465 порту установите `SMTP_SECURE=true`. Значение `APP_URL` должно указывать на
публичный адрес сайта, чтобы ссылки подтверждения в письмах открывались правильно.

## Платежи

Для будущей кассы в базе есть отдельная таблица `Payment`: она хранит провайдера,
статус, сумму, валюту, внешний идентификатор платежа и ссылку подтверждения.

Пока реальная касса не подключена, заказ в статусе `PENDING_PAYMENT` можно оплатить
в учебном режиме на странице `/orders/[id]/payment`. Запрос
`POST /api/orders/[id]/payments` создает или возвращает текущую платежную попытку,
а `PATCH /api/orders/[id]/payments/[paymentId]` завершает ее со статусом
`SUCCEEDED`, `FAILED` или `CANCELLED`.

Успешная учебная оплата переводит заказ в `PAID`. Отклоненная или отмененная
попытка остается в истории платежей, а заказ остается в `PENDING_PAYMENT`, чтобы
покупатель мог попробовать оплатить снова. Позже сюда можно подключить YooKassa:
использовать провайдера `YOOKASSA`, сохранять `externalId` и отправлять покупателя
по `confirmationUrl`.

## Пользователи

Регистрация и вход доступны на `/auth`. Новый пользователь сначала создается с
`emailVerified=false`, получает письмо со ссылкой `/api/auth/verify-email`, и только
после перехода по этой ссылке аккаунт активируется. До подтверждения email вход
запрещен.

Первый подтвержденный пользователь получает роль `ADMIN`, следующие пользователи
получают роль `CUSTOMER`. Личный кабинет находится на `/account`; админская страница
заказов `/admin/orders` доступна только администратору.

Администратор управляет пользователями на `/admin/users`: видит имя, email, статус
подтверждения, роль, блокировку, даты и активность. Поиск работает по имени, email
и телефонам из заказов. Администратор может менять роль и блокировать аккаунты, но
не может заблокировать себя или оставить сайт без активного администратора.

В личном кабинете пользователь может изменить имя и сменить пароль. Для смены
пароля нужно указать текущий пароль; после обновления старый пароль больше не
подходит.

Восстановление пароля доступно на `/auth/forgot-password`. Пользователь вводит email,
сайт отправляет письмо со ссылкой `/auth/reset-password?token=...`, ссылка действует
1 час. После задания нового пароля все токены восстановления этого пользователя
удаляются, старый пароль больше не подходит.

### Локальная настройка PostgreSQL

1. Создайте файл `.env` рядом с `package.json`.
2. Скопируйте в него строку из `.env.example` и замените `YOUR_PASSWORD` на пароль
   пользователя `postgres`.
3. Создайте базу данных:

```bash
createdb -h 127.0.0.1 -p 5432 -U postgres atelier_copies
```

4. Примените схему и загрузите стартовые товары:

```bash
npm.cmd run db:push
npm.cmd run db:seed
```

Если `createdb` не найден, запустите `createdb.exe` из папки `bin` вашей установки
PostgreSQL. Введите пароль, который задавали при установке.
